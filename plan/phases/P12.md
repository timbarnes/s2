# P12. How s2 compares with other Schemes

Done 2026-10-11. s2 was measured against eight established Schemes and
s1, on this machine. The results are in [07](../07-comparison.md).

- **Speed.** s2 is 1.8x slower than Gauche, the nearest design. It is 7x
  slower than Guile and 10-18x slower than the native-code compilers.
  It is 2.9x faster than chibi and 4.8x faster than s1. After NaN-boxing
  (D2), a rerun on 2026-10-12 gave 1.5x, 5x, 9-15x, 3.6x and 5.8x; 07
  now has that run's tables.
- **Conformance.** s2 passes everything in chibi's R7RS suite that it
  reaches. The one gap is complex numbers.
- **The benchmark runs found one bug in s2**, unbuffered file output (below).

## What was built

| File | Change |
|---|---|
| `bench/r7rs/run.sh` | runs ecraven's r7rs-benchmarks on any of ten systems: medians of interleaved rounds, iteration counts scaled down, a time limit |
| `bench/r7rs/summary.sh`, `scale.awk` | the medians table and the geometric mean relative to s2; scaling a benchmark's input |
| `bench/r7rs/name.scm` | the prelude for systems whose own prelude needs libraries not installed |
| `bench/r7rs/chez/scheme/*.sls` | R7RS's `(scheme base)` and friends as R6RS libraries, as much as the benchmarks need, so Chez runs them |
| `bench/r7rs/conformance.sh` | chibi's R7RS suite, section by section, on every system with R7RS libraries |
| `bench/r7rs/probe.scm` | a short program asking each system about its numbers and Unicode |
| `src/io.rs`, `heap.rs`, `builtins/port.rs`, `builtins/system.rs`, `main.rs` | file output ports are buffered, and flushed however s2 exits |
| `tests/process.rs` | a file left open is written in full, at a normal end, `exit`, `emergency-exit` and an error |
| `plan/07-comparison.md` | new: architecture, completeness, features and performance |

The suite is cloned into `target/` at a fixed commit, so the scripts add
no third-party code to the repository.

## How it was measured

**Benchmarks.**

- **Inputs.** The suite's inputs are sized to take about a second each on
  a native-code Scheme, which is about a minute on s2, or an hour per
  round. `run.sh -s 10` divides each iteration count by 10. A benchmark
  that already does one iteration runs at full size.
- **Timing.** Each program times itself, so a system's startup and
  compiling aren't counted. Chicken and Gambit compile to executables,
  and Guile and Racket compile ahead, all before the timed runs.
- **Medians.** Three rounds, the systems taking turns, as in P10. s1 ran
  in a round of its own against s2.

**Conformance.** Every system runs each section of the suite as a program,
through the same stand-in for `(chibi test)` that s2's own runner uses.

## Decisions

**Not Chez in the conformance table.** Chez is an R6RS system. Its reader
rejects R7RS syntax such as `#u8(...)`. The R7RS layer here was written
for the benchmarks, and has no `(scheme lazy)` or `cond-expand`. Testing
the layer would measure the layer, not Chez. s7 is left out too, as it has
no `import`.

**Not complex numbers.** The roadmap said programs s2 can't run would be
"fixed if the missing feature is R7RS". The only one is `mbrotZ`, which
needs complex numbers. P9 left them out on purpose. One benchmark doesn't
change that.

## Bug found

**File output was unbuffered.** Every `write-char` to a file was a system
call. In the benchmarks, `cat` (copying a file a character at a time) took
over 300 seconds on s2 and under 4 on every other system.

- **The fix.** File output ports now write through a `BufWriter`.
- **The risk.** A buffer can lose output a program wrote but never
  flushed. The heap now flushes every open file port before the process
  ends, whether by returning, `exit`, `emergency-exit`, or an uncaught
  error. A test checks all four.

`cat` now takes 2.1s.

## Findings for later phases

From the benchmarks where s2 is furthest behind Gauche (07):

- **Floating point.** s2 is 5-7x slower on `sumfp`, `pnpoly`, `mbrot` and
  `fibfp`. Flonums are unboxed, but the arithmetic instructions inline
  only the fixnum case, so every flonum operation goes through the
  general numeric code. A flonum case beside the fixnum one is a small
  change.
- **Vector and generic arithmetic loops** (`fft`, `puzzle`, `array1`,
  `earley`): 3-3.6x.
- **Allocation** (`gcbench`): 2.9x, against Gauche's Boehm collector.

None of these changes the design. They are candidates for a performance
phase after P13, if one is wanted.

The table in 07 is P13's baseline.

## Exit tests

- **The suite runs from one script:** `bench/r7rs/run.sh`.
- **s2's results are reproducible.** Within a run, s2's three times per
  benchmark differ by at most 10% (`primes`), and mostly by under 3%.
  Between the two runs, its medians agree within 0.94-1.10x. That is P10's
  noise.
