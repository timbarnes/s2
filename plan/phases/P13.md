### The oracle

`tests/compiler.rs` compiles a corpus with the Rust compiler and with
another `S2_COMPILER` choice, with `--expand --dis`, and requires the same
output line for line (C7). For now the other choice is `roundtrip`:

1. The Rust front end's AST becomes tagged vectors.
2. The vectors become an AST again.
3. The Rust codegen compiles it.
4. Every template is taken apart into `%make-template`'s arguments and
   made again, inner templates first.

This checks the converters that P13.1 needs, and the harness itself. A
deliberate change to one name in the round trip made the test fail, at the
right line of the right files.

**The corpus**, 58 files:

- **compiled only:** the golden files, `scheme/core.scm` and `bench/`;
- **run** (`-f`): the Scheme test files and chibi's suite, section by
  section.

Running gets past what compiling ahead can't do. `basic_tests` has a
circular constant, which compiled files can't hold. `library_tests`
writes a file and then includes it. Running also compiles what the
programs compile as they go (`eval`, `load`, library files), though only
the top-level forms are printed.

The whole test suite and chibi's suite also pass with
`S2_COMPILER=roundtrip`.

### Decisions

**The cargo feature waits for P13.5.** 08 had it in P13.0. Until P13.5
the Rust compiler is what builds the Scheme one, so a feature leaving it
out would have nothing it could leave out.

**Instruction names** are the `Op` names in kebab case (`local-ref`,
`jump-if-not-imm`), except the inlined predicates, which keep their
Scheme names (`null?`, `pair?`, `eq?`). A test in `JumpIfNot` is named
by its procedure (`<`, `null?`). One macro, listing each instruction once,
generates both directions, so the two can't disagree. A unit test round
trips every instruction.

### Bugs found

**Compiled files weren't reproducible**, as P11 noted. The cause: a
library environment's bindings were written in hash-table order, and the
table is keyed by addresses. Compiling the same file under GC stress gave
different bytes.

- **The fix:** sort the keys by name. Several hidden definitions can share
  a name: two `define-record-type`s in one library each make an `index`,
  keyed by different aliases. Those are ordered by where the code first
  uses what they are bound to.
- **The test** compiles a library with two record types, and `core.scm`,
  normally and under GC stress, and compares the bytes.

**A safety note, from P12.** The fixed value stack reads slots without
bounds checks in release builds. So a wrong slot index in a template,
from a damaged compiled file or a codegen bug, is now a memory error
rather than a panic. P11's note claiming otherwise is corrected.

`%make-template` checks everything it can without knowing the stack
depth: constant indexes, the kinds of constant instructions need, jump
targets and free-variable indexes. Slot indexes need a verifier that
tracks the depth through the code. 08's risks record it; until then, the
oracle and the debug-build test runs, where every access is checked,
stand in.
