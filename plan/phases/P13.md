# P13. The compiler in Scheme

Planned in [08](../08-compiler-in-scheme.md), which settles the decisions
(C1-C11) and splits the phase into P13.0-P13.6. This file records each
sub-phase as it is done.

## P13.0. Groundwork

Done 2026-10-12. Nothing of the Scheme compiler yet: the interfaces it
will use, and the harness that will check it.

### What was built

| File | Change |
|---|---|
| (tag) | `rust-compiler`, on the commit before P13.0: the Rust-compiled engine as it was |
| `src/compile/data.rs` | new: the core AST as tagged vectors and back (C2); instructions as lists and back, from one table; `%make-template`, which builds a template from its fields and checks its operands (C1); `%template-instructions`, its inverse |
| `src/compile/mod.rs` | `generate`, the one entry point for code generation, and `S2_COMPILER`: `rust` (the default) or `roundtrip` |
| `src/main.rs`, `libraries.rs` | every code generation goes through `generate`. `--expand` and `--dis` now also print during `--compile` |
| `src/fasl.rs` | compiled files are reproducible |
| `tests/compiler.rs` | new: the oracle, and a reproducibility test |

### The oracle

`tests/compiler.rs` compiles a corpus with the Rust compiler and with
another `S2_COMPILER` choice, with `--expand --dis`, and requires the same
output line for line (C7). For now the other choice is `roundtrip`:

1. The Rust front end's AST becomes tagged vectors.
2. The vectors become an AST again.
3. The Rust codegen compiles it.
4. Every template is taken apart into `%make-template`'s arguments and
   made again, inner templates first.

This checks the converters that P13.1 needs, and the harness itself. A
deliberate change to one name in the round trip made the test fail, at the
right line of the right files.

**The corpus**, 58 files:

- **compiled only:** the golden files, `scheme/core.scm` and `bench/`;
- **run** (`-f`): the Scheme test files and chibi's suite, section by
  section.

Running gets past what compiling ahead can't do. `basic_tests` has a
circular constant, which compiled files can't hold. `library_tests`
writes a file and then includes it. Running also compiles what the
programs compile as they go (`eval`, `load`, library files), though only
the top-level forms are printed.

The whole test suite and chibi's suite also pass with
`S2_COMPILER=roundtrip`.

### Decisions

**The cargo feature waits for P13.5.** 08 had it in P13.0. Until P13.5
the Rust compiler is what builds the Scheme one, so a feature leaving it
out would have nothing it could leave out.

**Instruction names** are the `Op` names in kebab case (`local-ref`,
`jump-if-not-imm`), except the inlined predicates, which keep their
Scheme names (`null?`, `pair?`, `eq?`). A test in `JumpIfNot` is named
by its procedure (`<`, `null?`). One macro, listing each instruction once,
generates both directions, so the two can't disagree. A unit test round
trips every instruction.

### Bugs found

**Compiled files weren't reproducible**, as P11 noted. The cause: a
library environment's bindings were written in hash-table order, and the
table is keyed by addresses. Compiling the same file under GC stress gave
different bytes.

- **The fix:** sort the keys by name. Several hidden definitions can share
  a name: two `define-record-type`s in one library each make an `index`,
  keyed by different aliases. Those are ordered by where the code first
  uses what they are bound to.
- **The test** compiles a library with two record types, and `core.scm`,
  normally and under GC stress, and compares the bytes.

**A safety note, from P12.** The fixed value stack reads slots without
bounds checks in release builds. So a wrong slot index in a template,
from a damaged compiled file or a codegen bug, is now a memory error
rather than a panic. P11's note claiming otherwise is corrected.

`%make-template` checks everything it can without knowing the stack
depth: constant indexes, the kinds of constant instructions need, jump
targets and free-variable indexes. Slot indexes need a verifier that
tracks the depth through the code. 08's risks record it; until then, the
oracle and the debug-build test runs, where every access is checked,
stand in.

### Tests

`cargo test` runs 114 tests, all passing:

- release, debug and GC stress builds;
- the whole suite again with `S2_COMPILER=roundtrip`;
- chibi's suite at 1154 in both modes.

## P13.1. Codegen and analysis in Scheme

Done 2026-10-12. The back end of the compiler is Scheme, and with
`S2_COMPILER=scheme` it compiles the corpus to exactly the Rust
compiler's code.

### What was built

| File | Change |
|---|---|
| `scheme/compiler/ast.scm` | the AST's accessors (the only code that indexes its vectors); a growable buffer; list helpers R7RS-small lacks |
| `scheme/compiler/analyze.scm` | free variables, boxed variables, lambda groups, as `analyze.rs` |
| `scheme/compiler/codegen.scm` | code generation, as `codegen.rs`, instruction for instruction |
| `src/main.rs` | the files, wrapped as the library `(s2 compiler)`, load from a cached image (`s2-compiler.s2o`), as `core.scm` does, when `S2_COMPILER=scheme`. `Session::generate` calls its `codegen` |
| `src/vm/machine.rs` | `Vm::call`: Rust calling a Scheme procedure, at the top level |
| `src/compile/data.rs` | `%inline-instruction`: which instruction a call to a global is inlined as, shared with the Rust codegen (`codegen::inline_op`) |
| `tests/compiler.rs` | the oracle checks `scheme` as well as `roundtrip` |

About 570 lines of Scheme, comments included, replace about 690 of Rust (`codegen.rs` and
`analyze.rs`).

### How it went

**The oracle earned its keep.** The first run differed on every file
that used `caddr`, which is in `(scheme cxr)`, not imported. The
compiler's error was raised as a Scheme error with a backtrace, through
the same machinery as any program's. After that one fix, the whole corpus
matched. That includes the Scheme test files and chibi's suite run in
full.

A deliberate change, disabling `sub-imm`, failed the test at the right
line of four files. Editing a compiler file and rebuilding also rebuilt
the stale image, as P11's freshness rule intends.

**Two runtime tests depended on the size of the startup heap**, and
failed with the compiler loaded:

- `tail_calls_run_in_constant_space` required the stack never to exceed
  64 slots. The compiler now runs on that stack. It now checks that a
  million iterations go no deeper than ten.
- `deep_recursion_collects_in_linear_time` bounded the marking per
  collection. Every collection also re-marks the startup heap, which the
  compiler enlarges. That part is now subtracted, and the linear bound on
  the rest is unchanged.

**A harness bug.** The two oracle tests ran their Rust-compiler pass under
the same temporary file names, in parallel, so one deleted the other's
files. Each test now names its own files.

### Decisions

Recorded in 08:

- **Analysis came with codegen** (P13.2 is folded in). Reaching the Rust
  analysis from Scheme would have needed primitives written to be
  discarded a sub-phase later.
- **The compiler is the library `(s2 compiler)`**, not `%` names in the
  system environment (C10 changed). Loading it from a compiled image
  needs no compiler, so the library machinery is no obstacle. Its names
  stay private.
- **Where the Scheme codegen runs.** It runs where the VM can call it: the
  REPL, `-e`, `-f`, programs and `--compile`. Library files and `eval`
  compile inside a primitive, so they keep the Rust codegen until P13.4.

### Measurements

Release build, wall time per run, the median of 20. Expansion is still
Rust, so the difference is the Scheme back end, plus converting each
form's AST to vectors and calling into the VM.

| | Rust | `S2_COMPILER=scheme` |
|---|---|---|
| Startup (`-e 1`) | 3.0ms | 3.5ms: the compiler's 30KB image |
| `--compile scheme/core.scm` (516 lines) | 4.0ms | 7.5ms |
| `--compile` four test files (1,034 lines) | 6.0ms | 18.5ms |

Less startup, compiling is 3.5-5 times slower: still a few milliseconds
per thousand lines. Nothing has been tuned. The likely costs are the
association lists for variable locations and names, and the linear
search of the constant pool.

### Tests

`cargo test` runs 115 tests, all passing:

- with the Rust compiler and with `S2_COMPILER=scheme`;
- release, debug, and GC stress with poisoning;
- chibi's suite at 1154 with either compiler.
