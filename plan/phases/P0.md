# P0. Skeleton: read and print

Done 2026-10-10. `s2` reads data and writes them back. There is no
evaluation yet.

```
$ s2 -e "(a . (b c)) 'x #(1 2/4) #0=(1 . #0#)"
(a b c)
(quote x)
#(1 1/2)
#0=(1 . #0#)
```

## Decisions

**D1 confirmed in practice.** Forking worked as 01 predicted:
- The tokenizer, number syntax, io and strings needed no changes beyond
  module paths.
- The parser and printer needed only their value type changed. Their logic,
  including datum labels and cycle printing, is untouched.

**D2: the value representation.**

- `Value` is a struct around a *private* enum (`Repr`). It is 16 bytes,
  `Copy`, and pinned by a `const` size assertion. Code outside `value.rs`
  can't match on the layout; it uses constructors (`Value::fixnum`,
  `Value::char`, `Value::NIL`, …) and accessors (`as_fixnum`, `as_obj`,
  `is_nil`, …). This enforces the rule in 03 §3 with the compiler rather
  than by convention, so a tagged word in P10 means changing one file.
- **Fixnums are 61-bit** (`FIXNUM_MIN`/`FIXNUM_MAX`), the range a tagged
  word with a 3-bit tag can hold. Representation changes then never change
  which integers are fixnums.
- **Every integer has exactly one representation.** `Heap::integer`
  returns a fixnum when the value fits, and a bignum only when it doesn't.
  `Heap::rational` returns an integer when the denominator is 1, so `4/2`
  reads as the fixnum `2`. `eqv?` will therefore never need to compare a
  fixnum with an equal bignum.
- **Flonums are unboxed** for now (the enum makes that free). A tagged word
  would box them again; that is a P10 trade-off to measure.
- **Two special values, kept apart as in s1:** `UNSPECIFIED` (the value of
  `display`, `set!` or `(if #f #f)`, which prints as nothing) and
  `UNDEFINED` (an unbound cell, or a `letrec` variable before
  initialisation, which prints as `#<undefined>`).
- `eq?` (`Value::eq`): identity for heap objects, value for immediates, and
  bit equality for flonums, so `(eq? x x)` holds even for a NaN.

**Object layout (03 §3).**

- `GcObject { mark: Cell<u64>, kind: Obj }`. The `Obj` kinds so far are
  `Pair`, `Symbol`, `Str`, `Vector`, `Bytevector`, `BigInt` and `Rational`.
- Mutable fields are `Cell<Value>` (pairs, vectors), `Cell<u8>`
  (bytevectors) or `RefCell<SString>` (strings). All access is through
  shared references, which removes s1's unsound `get_value_mut(&self)`. The
  parser's datum-label patching, which mutates pairs and vectors in place,
  is now safe code.
- `GcRef` wraps `NonNull<GcObject>`, so `Option<GcRef>` is 8 bytes. It is
  compared and hashed by identity.
- `GcRef::get` returns a reference with an **unbounded lifetime**.
  - A first version tied the result's lifetime to a borrow of the `GcRef`,
    which broke the printer's list loop.
  - The honest model is that the GC, not the borrow checker, decides how
    long an object lives. So the one `unsafe` dereference states that
    invariant, and nothing else pretends otherwise.
  - That invariant is the thing P3 must make true: an object stays alive
    while it is reachable from the roots, and collection happens only at
    safepoints.

**No collection yet.** Objects live until the `Heap` is dropped, which
frees them all. The `mark` field is already in place for P3.

**Smaller choices:**

- **No `lib.rs`.** A single binary crate is enough. Process tests run the
  binary (`CARGO_BIN_EXE_s2`), and the other tests live in the modules.
  Add `lib.rs` when a second binary arrives (P11) or integration tests need
  internal APIs.
- **No `argh`.** `std::env::args` covers `-e TEXT`. Add a parser when
  there are enough flags to justify one (`--dis` and `--expand` in P1/P5
  may get there).
- **No mimalloc yet.** It is a performance item, added when P2 starts
  measuring against s1. s1 uses it, so comparisons should be like for like.
- **The printer is cut to the reader's types.** s1's printer also handled
  procedures, ports, records, error objects, environments and
  continuations; those cases come back with the phases that add the types.
  `write-shared` and `write-simple` were kept, because they are part of the
  label logic and are tested now.
- **`#[allow(dead_code)]` on the forked and foundation modules.** They
  carry API that later phases use, such as `FileTable` and port predicates
  (P6) and the GC mark (P3). Remove the allows as callers appear.
- **Two clippy suggestions in forked code** (collapsible `if`s in `io.rs`
  and `tokenizer.rs`) are left alone, so the forks stay faithful.

## Tests

`cargo test` runs 45 tests, all passing:

- **s1's tokenizer and number-syntax unit tests** (forked unchanged), and
  s1's sstring tests.
- **s1's parser tests, rewritten** to compare written output instead of
  matching nested structures. The cases are the same (atoms, lists, dotted
  pairs, vectors, quotes, datum comments, datum labels, deferred errors that
  keep the reader in sync, `|...|` symbols). There are new assertions on
  which number kind each literal produces.
- **s1's printer tests, ported:** escapes, float formatting, `|...|`
  symbols, display versus write. A new test covers shared and cyclic
  structure.
- **The P0 exit test** (`parser::tests::round_trip`): about 30 inputs whose
  written form is the input itself, from fixnum and bignum boundaries to
  cyclic lists and vectors. Also about 15 inputs with a canonical written
  form: `'x`, `#true`, `#x1F`, `#e1.5`, `#\x41`, block comments,
  `#!fold-case`, `[1 2]`.
- `value` and `heap` unit tests: the fixnum range, normalisation,
  interning, `eq?`.
- **Process tests** (`tests/cli.rs`): `-e`, stdin without a terminal (no
  prompt), syntax errors (reported on stderr, reading continues, exit
  status 1), bad usage (exit status 2).

## Surprises

- The round-trip corpus first listed `#\x3bb` as an input that writes back
  unchanged. It writes as `#\λ`, which is correct: `write` uses the
  character itself when it is printable. The case moved to the canonical
  list.
- See the `GcRef::get` lifetime note above.
