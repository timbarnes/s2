# P1. The first compiler and VM

Done 2026-10-10. Every top-level form is compiled to bytecode and run.
There are no procedures yet beyond the builtins.

```
$ s2 --dis -e "(define x 10) (if (< x 20) (+ x 1) 0)"
template top-level
   0  Fixnum 10
   1  GlobalDefine k0  ; x
   2  Return
x
template top-level
   0  GlobalRef k0     ; <
   1  GlobalRef k1     ; x
   2  Fixnum 20
   3  Call 2
   4  JumpIfFalse →10
   5  GlobalRef k2     ; +
   6  GlobalRef k1     ; x
   7  Fixnum 1
   8  Call 2
   9  Jump →11
  10  Fixnum 0
  11  Return
11
```

## The pipeline, as built

```
text ──reader──▶ datum ──expand.rs──▶ Expr ──codegen.rs──▶ Template ──machine.rs──▶ Value
                           (looks up / creates            (Vec<Op> +
                            binding cells in Env)          constant pool)
```

`Session::eval` in `main.rs` is the whole pipeline in four lines. It is
used by the REPL, by `-e` and by file mode.

## Decisions

**D4: a stack VM.** The rule that makes codegen simple: *the code for every
expression leaves exactly one value on the stack.*

- A call pushes the procedure, then each argument left to right, then
  `Call n`, which replaces all `n + 1` values with the result.
- `begin` emits `Pop` between expressions.
- `define` pushes the variable's name after storing (`GlobalDefine`), so
  even it obeys the rule. Returning the name matches s1 (`(define x 1)`
  prints `x`).

P1 has no frames: a template runs from instruction 0 to its `Return`, and
the stack is a local `Vec` in `vm::run`. Frames, and a `Vm` struct to hold
them, come with `lambda` in P2.

**D5: `enum Op`.** 13 instructions, 8 bytes each (pinned by a size
assertion). The instruction set:

- `Const k`, `Fixnum n`, `Nil`, `True`, `False` and `Unspecified` push
  constants;
- `GlobalRef k` and `GlobalDefine k` read and write globals;
- `Jump t`, `JumpIfFalse t` and `Pop` handle control;
- `Call n` and `Return` handle calls.

Fixnums that fit an `i32`, `'()`, booleans and the unspecified value get
their own instructions, so they need no pool entry. Every other literal
goes in the constant pool.

**Jump targets are absolute** (an index into the template's code), not
relative offsets as 03 §6 sketched. In a `Vec<Op>` both are equally cheap.
Absolute targets read directly in the disassembly (`JumpIfFalse →10`) and
make patching one assignment. Relative offsets matter only for
position-independent byte code, which is a P11 question.

**D7: binding cells in the constant pool.**

- A cell is a heap object, `Obj::Global { name, value }`. `Env` maps
  symbols to cells.
- The *expander* resolves each global name. It creates an unbound cell
  (holding `UNDEFINED`) if the name is new, and puts the cell itself into
  the AST.
- Codegen puts the cell in the constant pool, so `GlobalRef k` is one load
  plus an unbound check, with no lookup by name at run time.
- Late binding follows for free. Compiling a reference to a variable not
  yet defined creates its cell; `define` fills the same cell later, and a
  redefinition is seen by every template that holds it.
- The cost: a typo'd name leaves an unbound cell in `Env` forever. That is
  harmless, and s1 behaves the same way.

**How a top-level form becomes a thunk.** Each form compiles to one
`Template` named `top-level`, and `vm::run` runs it. A template has no
arity yet, because P1 templates never take arguments. `arity` and `nfree`
join `Template` in P2, when templates are used for `lambda` too.

**Builtins.**

- A builtin is `fn(&mut Heap, &[Value]) -> Result<Value, String>`, the s1
  signature, so s1's builtins can be ported in P6. It is wrapped in a
  `Primitive { name, min, max, f }`. The *VM* checks the argument count
  before calling, so builtins don't repeat that check.
- A primitive is a heap object (`Obj::Primitive(&'static Primitive)`) that
  points at a static table, so installing the builtins allocates one small
  object each.

**Errors.** No `raise` yet. An `Err` from a builtin, the expander or the VM
(unbound variable, calling a non-procedure, wrong argument count) aborts
the current form. The message is printed to stderr as `error: …`, and
evaluation continues with the next form. The exit status is 1 if any form
failed, as for syntax errors in P0.

**Arithmetic is fixnum-only** on input, but results overflow correctly into
bignums: `+` and `-` work in `i128`, and `*` in `BigInt`. A bignum given as
an argument is an error (`+: not a fixnum`). This is a deliberate stopgap
until P6 brings s1's numeric tower. The alternative, wrapping or erroring
on overflow, would give wrong answers silently.

**The minimal expander** recognises the four keywords by name, so they
can't be shadowed, and it allows `define` only at top level (including
inside a top-level `begin`). It follows R7RS where s1 is more lenient:

- `()` is an error ("empty combination"), not a constant;
- `<`, `=` and `>` need at least two arguments, as in s1.

**CLI.**

- `s2 FILE` runs a program without writing results, the way s1 runs a
  script; it is needed for differential tests.
- `-e` and the REPL write each result. The unspecified value writes
  nothing.
- `--dis` prints each template before running it, so its output
  interleaves code, output and results in execution order.

**`Value::as_obj` now returns an unbounded lifetime,** like `GcRef::get`.
The expander's `car.get().as_obj()` borrowed a temporary. Same reasoning
as P0: the GC, not the borrow checker, decides how long an object lives.

## Tests

`cargo test` runs 56 tests, all passing:

- **Result tests** (`main.rs`): constants, arithmetic, bignum overflow,
  nested calls, `if` and truthiness (only `#f` is false), `define` and
  redefinition, and errors. The error tests include the P1 exit test: an
  unbound variable reports an error, and the next form runs.
- **Golden disassembly** (`tests/golden/*.scm` → `*.dis`): constants,
  define, if, nested calls, begin, and an unbound variable. Each `.dis` is
  `s2 --dis FILE`'s stdout and stderr. Regenerate them with
  `UPDATE_GOLDEN=1 cargo test --test golden` and review the diff.
- **Differential** (`tests/diff/*.scm`): s2 and s1 must print the same
  thing. s1 is found through `S1_BIN`, and the test is skipped, with a
  note, when s1 can't be run. Run it with:
  `S1_BIN=path/to/s1 cargo test --test diff`.
- **Process tests:** `-e`, stdin, a runtime error that doesn't stop
  evaluation, file mode, and usage.

## Surprises

- `../s1/target/release/s1` is a Linux x86 binary on this Mac. For this
  phase s1 was rebuilt into a scratch target directory, without touching
  s1's tree, and passed in through `S1_BIN`. Executing the Linux binary
  doesn't fail to spawn: it runs and exits with a failure status, so the
  "is s1 available" check tests `--help`'s exit status.
- The first result test had a bare `()` in it, which the compiler
  correctly rejected.
- The `(if #f #f)` golden shows `False; JumpIfFalse` on a constant: there
  is no constant folding. That is deliberate. P10 may add it.

## Addendum: VM primitives and `dis`

Added after P1, at the user's request, as a step before P2.

```
s2> (dis '(+ 2 3))
template top-level
   0  GlobalRef k0     ; +
   1  Fixnum 2
   2  Fixnum 3
   3  Call 2
   4  Return
```

`(dis datum)` compiles `datum` as a top-level form, for the current
environment, and prints the listing without running it.

**Why it needed a new kind of primitive.** A builtin only gets the heap and
its arguments. Compiling also needs the top-level environment, so that
global names resolve to the right cells. `eval` has the same need. So
this brings forward the second kind of primitive from 03 §11 (D9's
option b):

- `Primitive.f` is now `PrimFn::Builtin(fn(&mut Heap, &[Value]))` or
  `PrimFn::Vm(fn(&mut Heap, &mut Env, &[Value]))`.
- Both are ordinary procedure values, with the same arity check and the
  same `Call` instruction. Only the dispatch inside `Call` differs.
- `vm::run` now takes the `Env` the code was compiled for, and passes it on.

**Deliberately incomplete.** A VM primitive returns a plain value, which is
all `dis` needs. In P7 it will return an `Action` (`Return`, `TailCall`,
`Resume`), so that `eval` can tail-call the template it compiles and
`%call/cc` can resume a continuation. It will also receive the VM rather
than just the `Env`.

**Side effect.** `(dis '(define y 1))` creates an unbound cell for `y`
without defining it, as compiling any reference to a new name does. This
is harmless.

**Tests:** a golden case (`tests/golden/dis.scm`) and a process test
covering the output without `--dis` and a compile error inside `dis`.
