## Decisions

**Complex numbers stay out** (decided with the user). s1 doesn't have
them, nothing else in R7RS-small depends on them, and they cost a new
number representation, reader syntax and extensions to every numeric
procedure. `(scheme complex)`'s six procedures stay unimplemented, and the
suite's unreached tests, nearly all of them complex numbers, are the same
as s1's.

**Source locations come later**, after P10 (decided with the user).
Nothing depends on them, and they touch the reader, the expander and code
generation, which P10 may reshape for speed. The backtrace already names
the procedures.

**Auxiliary syntax is bound.** `else`, `=>`, `_` and `...` are core forms
of the system environment that do nothing but exist, like s1's. So:

- `(scheme base)` exports them, and they can be imported, renamed or left
  out like any binding;
- a macro's literal matches them by binding (P5's `free-identifier=?`).
  So `cond` recognises `else` imported under another name, and not a local
  variable named `else`;
- used as an expression they are an error: `else: auxiliary syntax can't
  be used as an expression`;
- `syntax-rules` still finds `_` and `...` in patterns by name, as s1's
  matcher does.

**`syntax-error`** is a core form. Expanding it is an error, so a macro
whose template reaches it fails when the use is expanded (R7RS §4.3.3).
Its irritants are written after the message. s1 reports it at run time,
as an error object whose irritants are the unevaluated forms. In s2 it
happens while compiling, so the irritants go in the message, which is
all that survives a compile error (see P8 on compile-time errors).

**`map` and `for-each` accept zero lists**, giving the empty list and
doing nothing, as in s1, whose tests check it. R7RS calls it an error.

## Porting s1's regression files

The rule from plan/05 §4: change a test only to remove an s1 extension,
never to change what it expects. Each file's header lists its changes.
They fall into five kinds:

- **s1 extensions** left out, or replaced by their R7RS equivalent:
  - `nil`, `float?`, `type-of`, `>string`, `displayln` and s1's `macro`
    form;
  - one-argument `eval`, given `(interaction-environment)` instead;
  - `%kont-depth`, which is `%frame-depth` in s2.
- **s1 behaviour R7RS leaves open or forbids**:
  - a `define` inside a `cond` clause, or as the whole body of a `guard`
    (s1 defines a global);
  - the value of `vector-fill!`, and what `make-vector` fills with when
    given no fill.
- **Compiling ahead** (P5, P8). Errors s2 finds while expanding a
  top-level form can't be caught by a `guard` in that form, so those tests
  go through `eval`. Two tests of s1's expansion cache (a macro redefined
  after code using it ran) are left out.
- **Error wording.** s2's arity and type errors name the procedure and
  the expected count or type, where s1's say "too many arguments" or
  "name must be a string". `case-lambda`'s message is now s1's.
- **One reader difference.** s1's test used `#t-or-ev?` as an
  identifier, which R7RS doesn't allow (§7.1.1) and s2's reader rejects.
  Renamed `t-or-ev?`, the three macros give `(#f #t)`, worked by hand.
  s1's expected `(#t #f)` came from how its reader split the invalid
  token. This is the one test whose expected value changed.

What was left out entirely:

- `macro_tests.scm` except its quasiquote section, since the rest tests
  s1's `macro`. Its hygiene tests are in `syntax_rules_tests.scm`.
- `help_tests.scm`, `gc_tests.scm` and `gc_stress_tests.scm`, which test
  s1's `help`, `gc-threshold` and stress settings. s2's stress mode runs
  every test file instead.

P7's `control_tests.scm` was a copy of `advanced_tests.scm`'s
`dynamic-wind` section, and is gone now that the whole file is ported.

## Bugs found

- **`(- 0.0)` was `0.0`.** P6's unary minus computed `0 - x`, which loses
  the sign of a zero. It now negates.
- **`#t-or-ev?`**: not a bug in s2, but a test that relied on s1's reader
  accepting an invalid identifier (above).
